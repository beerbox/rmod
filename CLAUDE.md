# rmod: local LLM monitor mod for Claude Code

rmod is a Claude Code **mod**: a plugin whose TypeScript hooks module runs inside Claude Code. It shows whether a local **Ollama** server and a local **LM Studio** server are listening. It counts the requests this session sends to local models, with timings, and lists the local models that are available. The target machine is a **MacBook** (Apple Silicon, macOS), and the mod is used from the terminal CLI and the Code tab of the Desktop app.

## Source of truth: always the latest documentation, never memory

The mods API is in early access and changes between Claude Code releases. Your training data about it is probably wrong or stale. Before writing or changing mod code, use these sources in this order:

1. **The generated types for the installed build**: `.claude-plugin/types/claude-code/index.d.ts`, plus `claude-code-tools/`, `claude-code-mcp/` and `tsconfig.json`. Claude Code writes them each time it loads the mod with `--plugin-dir`. Its first line names the version. Grep it for the name you need (`'tool.call'`, `'turn.step'`, `HttpInit`, `AbovePrompt`) and read the declaration. **When these types and any document disagree, the types win.**
2. **The built-in `plugin-authoring` skill** (`/plugin-authoring`). Its `reference.md` and `examples/` match the running build.
3. **Live docs at code.claude.com.** Fetch the `.md` form of the page, for example `https://code.claude.com/docs/en/plugins/mods/reference.md`. The index of all pages is `https://code.claude.com/docs/llms.txt`. Use WebFetch every time and never quote from memory.
4. **Live docs for the local servers**: `https://docs.ollama.com/api` and `https://lmstudio.ai/docs/developer/rest`. Server APIs change too.
5. **This repo's `docs/`**, which can go stale. If you find drift, fix the doc in the same change.

Run `/docs-check` at the start of any session that touches the mods API, after a Claude Code update, or when `docs/REFERENCES.md` says "last verified" more than 14 days ago. The SessionStart hook in `.claude/settings.json` prints the installed Claude Code version into context.

## Project layout (the repo root is the plugin root)

```
.claude-plugin/plugin.json      manifest (name "rmod"; never prefix with "claude-")
.claude-plugin/types/           GENERATED by Claude Code at load. Gitignored. Do not edit.
hooks/hooks.json                { "modules": ["./register.tsx"] }: exactly one path
hooks/register.tsx              entry: export const register: Register = (on, options) => { ... }
hooks/lib/*.ts                  pure logic (no `$`): url guard, parsers, stats, attribution
hooks/ui/*.tsx                  render helpers that take ($, e, data) and return element trees
types/index.d.ts                $.state contract (interface PluginState { rmod: {...} })
tests/**/*.test.ts              `claude plugin test` suites; tests/fixtures/*.json = real API samples
.claude/                        Claude Code project config for DEVELOPING the mod (not shipped)
docs/                           spec, architecture, plan, testing, security, references
```

Do not put anything in a root-level `skills/`, `agents/` or `commands/` folder. Those load as plugin components and would ship to users. Development skills and agents go in `.claude/`.

## Development rules

- **Workflow**: pick the next unchecked item in `docs/PLAN.md`, then run `/implement-milestone <id>`. Write a failing test, implement, run `/verify`, update PLAN.md, and commit. Commit small and often, and use Conventional Commits (`feat:`, `fix:`, `test:`, `docs:`, `chore:`).
- **Static-analysis rules** (or `claude plugin validate` fails): write every API call in full as `$.noun.method(...)`. Never alias, destructure or index `$`. Every `on('event', ...)` name is a string literal. No dynamic `import()`. ES modules only. Import only from relative paths and `'claude-code'`. Don't shadow `on`. Register `session.start` once, with no matcher.
- **Never block the user**: every observing hook returns `next(e)` (or the awaited result) unchanged. Wrap the mod's own work in `try/catch` so a failure in rmod never denies or alters a tool call, prompt or model request. rmod is an observer and never a gate. Don't add `.catch(... deny ...)` handlers.
- **Hook budget**: about 10 s per hook, and time spent in `$` calls doesn't count. Keep render hooks fast and pure. Do slow work in `$.clock.every` timers started from `session.start`.
- **State**: values a drawing reads live in `$.state`, declared in `types/index.d.ts` and used through `atom` / `read` / `update` from `'claude-code'`. Module variables reset on every hot reload. `$.store` is only for user preferences that should outlive the session.
- **Surfaces**: draw for `terminal` and `desktop`. Use `$.ui.resolve(e)` for elements and check `e.surface` before using terminal-only elements (`Raster`, `Image`). Where nothing draws (`claude -p`, VS Code), fall back to `$.ui.status` or the `/rmod-status` text.
- **TypeScript**: `strict`, no `any` (use `unknown` and narrow it), no non-null `!` on external data. Validate all JSON from the servers before use, because it is untrusted input.
- **Keep files small**: one concern per file in `hooks/lib/`. Pure functions get plain unit tests.

## Security (non-negotiable; full model in docs/SECURITY.md)

- **Loopback only**: rmod sends HTTP only to `127.0.0.1`, `::1` or `localhost`, on the configured ports. Any other host in config is rejected. No internet calls from the mod at all.
- **Metadata only**: never store, log or display prompt text, model output, Bash command text or file contents. Counters, timings, model names and status codes only.
- **No secrets in the repo**: the optional LM Studio API token is a `userConfig` field with `"sensitive": true`, so it goes to the macOS Keychain. Never write it to settings, logs, `$.store`, toasts or tests. Use obviously fake tokens in fixtures.
- **Least privilege**: the mod may call only the `$` methods allowlisted in docs/SECURITY.md. It must not use `$.process`, `$.fs` writes, `$.model`, `$.prompt.submit`, `$.session.send` or `tool.check`. `/verify` enforces this from `claude plugin validate` output.
- **Bounded resources**: ring buffers capped at 200 samples, polling no faster than every 2 s, a timeout on every probe, and no unbounded arrays in `$.state`.
- Never read or print `.env*`, keys, `~/.ssh`, `~/.aws` or Keychain data. Permission rules in `.claude/settings.json` deny these too.
- Before every commit, the gitleaks pre-commit hook must pass. Never use `--no-verify`.
